# Cross-repository surfaces

> Generated by `scripts/architecture.py`; edit `registry/surfaces.toml`, not this file.

A surface is the narrow contract at a repository boundary. Shared implementation is not implied.

## agent-pet-event-v1

- Location: `io.github.masonrhodesdev.AgentPet1`
- Compatibility: Future major event versions are rejected; unknown additive fields are tolerated.
- Failure behavior: Hook sends are capped at 500 ms and intentionally never fail the calling harness.
- Barriers: BAR-005, BAR-007, BAR-010, BAR-014

## agent-pet-skin-v1

- Location: `$XDG_CONFIG_HOME/agent-pet/pets/<id>`
- Compatibility: Version changes row layout; required animation tracks and fallbacks need a published schema.
- Failure behavior: Invalid skins are rejected and the renderer falls back to the packaged pet.
- Barriers: BAR-005, BAR-007, BAR-012

## appearance-profile-v1

- Location: `/usr/share, /etc, XDG config, and /var/lib/appearance-profiles`
- Compatibility: Fields resolve independently through packaged, system, user, and runtime layers.
- Failure behavior: Unreadable layers are skipped with diagnostics; application fallback remains available.
- Barriers: BAR-003, BAR-004, BAR-007

## desktop-dpms-arbitration-v0

- Location: `hyprstate locked/inhibited timer and hypridle listeners`
- Compatibility: Trigger domains need explicit precedence and race rules so ordinary idle and protected lock policy do not fight.
- Failure behavior: Competing writes can wake, blank, or reblank displays contrary to the latest user/session state.
- Barriers: BAR-001, BAR-007, BAR-012, BAR-014, BAR-025

## game-mode-approval-v1

- Location: `/run/access-gate/ctrl.sock and access-gate-verifier`
- Compatibility: Approval requests and status replies are newline-delimited JSON; passkey verification is the authority.
- Failure behavior: Every unavailable, malformed, denied, or timed-out path remains at the greeter.
- Barriers: BAR-007, BAR-011, BAR-016, BAR-021, BAR-025

## game-mode-armed-v1

- Location: `/run/game-mode/armed`
- Compatibility: The armed flag is consumed once and expires after 60 seconds.
- Failure behavior: Restart failure currently leaves the flag fresh, allowing a later greetd restart to enter game mode unexpectedly.
- Barriers: BAR-004, BAR-007, BAR-011, BAR-013, BAR-016, BAR-025

## game-mode-home-mask-v0

- Location: `game-mode-wrapper and current $GAMES_DIR/.game-mode-no-mask override`
- Compatibility: The bind policy is the security boundary for game-session home access.
- Failure behavior: The protected games user can currently create the permanent bypass file; the override must move to a root-owned path.
- Barriers: BAR-011, BAR-017, BAR-021

## graphical-session-lifecycle-v0

- Location: `graphical-session.target and packaged user units`
- Compatibility: Services must bind startup and teardown to the graphical session and explicitly pull required audio, tray, and compositor dependencies.
- Failure behavior: Incomplete PartOf/Requisite/Wants relationships leave services running outside their usable session or absent when expected.
- Barriers: BAR-007, BAR-009, BAR-014, BAR-018

## greetd-greeter-v1

- Location: `/run/greetd.sock and /etc/greetd`
- Compatibility: Greeters implement the greetd request/response protocol; session entries follow XDG conventions.
- Failure behavior: Authentication and alternate-session entry fail closed at the greeter.
- Barriers: BAR-004, BAR-007, BAR-011, BAR-012

## greetd-static-config-v1

- Location: `/etc/greetd/config.toml and related /etc/greetd payload`
- Compatibility: greetd-game-mode is the current owner; greetd-config remains a conflicting functional predecessor.
- Failure behavior: Running both setup paths rewrites or symlinks the same tree and can leave the login path incoherent.
- Barriers: BAR-001, BAR-004, BAR-013, BAR-018, BAR-019

## hypr-de-help-v0

## hypr-ipc-v0

- Location: `hypr_ipc::socket2_path, hypr_ipc::connect_socket2, hypr_ipc::hyprctl_ok`

## secure-suspend-v0

## settings-entry-v1

- Location: `$XDG_DATA_HOME/applications and $XDG_DATA_DIRS/applications; Categories=Settings; or X-Dials-Section=<Appearance|Hardware|Network|System|Other>`
- Compatibility: Categories=Settings; is the freedesktop convention and also lists the entry in LXQt and Xfce settings managers. X-Dials-Section only picks the group. NoDisplay, Hidden, OnlyShowIn/NotShowIn, and a missing TryExec hide an entry. Exec field codes are dropped.
- Failure behavior: A tool without a desktop entry is simply not listed; dials never embeds or imports another tool.
- Barriers: BAR-001, BAR-012
