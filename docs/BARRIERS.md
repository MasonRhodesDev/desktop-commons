# Architecture barriers

> Generated by `scripts/architecture.py`; edit `registry/barriers.toml`, not this file.

Barriers are review and CI constraints. They prevent ownership drift while allowing implementations to evolve independently.

| ID | Name | Severity | Rule |
|---|---|---|---|
| BAR-001 | single-writer | error | Every mutable system concern has one authoritative writer; other components request or observe through a declared surface. |
| BAR-002 | ui-is-a-client | error | Settings and status surfaces do not independently implement runtime policy or mutate hardware behind the owning daemon. |
| BAR-003 | neutral-contract | error | Cross-environment source data remains compositor-neutral; Hyprland syntax is generated only at the adapter boundary. |
| BAR-004 | prelogin-home-boundary | error | Pre-login components cannot require access to a private user home and consume only system or published snapshots. |
| BAR-005 | declared-surface | error | A repository may consume another repository only through a registered file, protocol, library, executable, or service surface. |
| BAR-006 | acyclic-runtime-dependencies | error | Runtime repository dependencies are directed and acyclic; callbacks use protocols rather than reverse package dependencies. |
| BAR-007 | version-and-failure-contract | error | Every cross-repository surface states compatibility, failure behavior, and an owner responsible for evolution. |
| BAR-008 | evidence-before-extraction | warning | Shared implementation is extracted only after at least two real consumers converge on behavior; until then share contracts and test vectors. |
| BAR-009 | standard-lifecycle | error | Distributable components use package-owned payloads, shared release workflows, systemd lifecycle, and no checkout-symlinked executable. |
| BAR-010 | unique-namespace-owner | error | D-Bus names, sockets, state files, configuration paths, systemd units, and privileged interfaces have one registered owner. |
| BAR-011 | narrow-privilege | error | Policy remains unprivileged; privileged mechanisms expose a minimal allowlisted interface and never execute user-writable code. |
| BAR-012 | external-provider-explicit | warning | Desktop capabilities supplied externally name the selected provider, integration seam, fallback, and replacement policy. |
| BAR-013 | one-active-path | error | Legacy and replacement implementations may coexist during migration, but only one path is active and the retirement condition is recorded. |
| BAR-014 | daemon-reconciliation | warning | Long-running state owners reconnect with rediscovery, reconcile against ground truth, and expose liveness and diagnostics. |
| BAR-015 | generated-architecture | error | Human-facing relationship and coverage documents are generated from validated registries rather than maintained as independent truth. |
| BAR-016 | secure-transition | error | Suspend, logout, and protected-session transitions require positive lock or teardown readiness; timeout cannot silently continue fail-open. |
| BAR-017 | no-unprivileged-security-bypass | error | A protected mode cannot be disabled through a file, environment value, or control path writable by the protected principal. |
| BAR-018 | activation-complete | error | Installation composes every required service and dependency, or explicitly gates the unavailable capability and reports it in doctor output. |
| BAR-019 | operator-config-preservation | error | Package upgrades preserve documented operator-edited authentication, security, and policy files. |
| BAR-020 | session-scoped-detection | error | Session and lock discovery uses session identity or protocol state, never machine-wide process-name matching. |
| BAR-021 | privilege-minimization | error | Device groups, capabilities, sudo commands, and filesystem access require a current call-site and are narrower than the protected data they expose. |
| BAR-022 | immutable-supply-chain | error | Privileged reusable workflows, actions, base images, source archives, and package inputs are pinned and packages carry verifiable integrity metadata. |
| BAR-023 | release-gated | error | A release cannot publish unless required package, test, security, and contract checks for that platform succeed. |
| BAR-024 | registry-completeness | error | Package repositories publish against an expected package/version manifest and fail rather than silently serving a partial or stale set. |
| BAR-025 | authoritative-state | error | One protocol or owner is authoritative for runtime state; side-channel files cannot report success when the owning service did not receive a request. |
