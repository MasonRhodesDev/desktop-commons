## Cross-cutting findings

**Already consistent (de-facto standards — codify them):**
- Rust tools: tokio + tracing/tracing-subscriber + clap derive + anyhow(/thiserror), Cargo.lock always committed. zbus wherever D-Bus is needed (lmtt is on zbus 4; everything else 5).
- C++ tools: hypr-ecosystem stack (hyprutils/hyprlang/hyprtoolkit + sdbus-c++), CMake.
- systemd units target graphical-session.target (user) / multi-user.target (system); journald via stdout.
- TOML at `~/.config/<tool>/` for Rust tools.

**Fragmented (the convergence work):**
- **Install**: symlink installers (hyprnotice, greetd-config), Makefiles (3 tools, different targets: ~/.local/bin vs /usr/local/bin), an RPM spec (logind-idle-control), an AUR PKGBUILD (voice-dictation), a bespoke bash installer with sudoers (greetd_game_mode), nothing (couchcord, waybar-buttons). hyprstate just established dist/ + packaging/ (RPM+COPR and PKGBUILD from one tag) — the convergence target.
- **D-Bus naming**: `org.hyprstate.Power1`, `com.voicedictation.Daemon`, `com.logind.IdleControl` — three namespace styles, two squatting domains not owned.
- **Hot reload**: SIGHUP (hyprnotice), file watcher (voice-dictation), none/restart (everything else). No consensus.
- **Testing**: 56 unit tests (couchcord) and 52 (hyprstate) where a pure core exists; zero elsewhere. The correlation is the lesson: testability came from the architecture, not from discipline.

**Duplicated implementations (consolidation candidates):**
1. **Hyprland socket2 reading** ×4: hyprstate v2 (instance rediscovery, the best), waybar-workspace-buttons (C, raw + sleep(1) retry), hyprdm (C++ CHyprIPC), voice-dictation (hyprctl shelling instead).
2. **logind interaction** ×3: hyprstate (manager/session proxies, lid inhibitor fd), logind-idle-control (inhibitor RAII, session resolution w/ XDG_SESSION_ID fallback), voice-dictation (idle inhibit during recording). Each hand-rolls proxies + session resolution.
3. **hyprctl JSON querying** ×4 with three quality levels (typed async wrappers vs popen+jq+sscanf).
4. **`#@` / directive-comment config parsing** ×2 dialects inside hyprstate alone.

**Feature overlap needing a decision:**
- **hyprdm duplicates hyprstate's monitor-profile subsystem** (priority-ranked profiles auto-applied on monitor hotplug). hyprstate's is in production (signature matching, debounced reconcile, .active.conf contract); hyprdm is a v0 scaffold whose differentiators are per-monitor mode/scale editing and a GUI. Options: fold hyprdm's editor ambitions into a `hyprstate profile` GUI/TUI (schema-tui?), or scope hyprdm strictly to the *editor* and have it emit hyprstate profiles.

**Implicit cross-tool contracts discovered (currently undocumented):**
- hyprstate's inhibitor baseline allowlist hardcodes `logind-idle-control`, `hypridle`, its own names — i.e. the suite already relies on a "tools use their canonical name as the logind inhibitor `who`" convention. One rename breaks lid behavior silently.
- lmtt pokes hyprnotice with SIGHUP after theme switches; waybar-buttons greps lmtt's colors css; hyprstate's waybar module + notification tags. The suite is a web of small contracts that live only in code.
